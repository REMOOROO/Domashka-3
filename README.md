## 1. О чём работа

Исследуется логистическая регрессия и её расширения (полиномиальные признаки, L1/L2-регуляризация, веса классов, подбор порога, `SGDClassifier`) на двух типах данных:

1. **Синтетические данные** — набор «Инь-Ян» с нелинейной границей классов; изучаются недообучение, переобучение и роль регуляризации (3.1–3.4).
2. **Реальные данные** — *Adult Census Income*: предсказание, превышает ли доход человека 50 000 $; полный цикл EDA → предобработка → baseline → улучшение → анализ ошибок → выводы (4.1–4.5).

## 5. Методология

### Часть I. Синтетические данные
- **Генерация:** собственная функция «Инь-Ян» (два вложенных полукруга с «глазками»), стратифицированное разбиение 70/30.
- **Модель:** `PolynomialFeatures → StandardScaler → LogisticRegression`.
- **Подбор сложности:** степени 1–15; метрики — accuracy и **log-loss** (log-loss показывает переобучение раньше accuracy). Границы решений рисуются через `contourf` по `predict_proba`.
- **Регуляризация** на избыточной степени 15: L2 и L1, перебор `C`; для L1 — число ненулевых весов.
- **Артефакты:** веса (`coef_`, `intercept_`), метрики (accuracy, precision, recall, F1, ROC-AUC, log-loss), матрица ошибок, ROC-кривая, ручная проверка `predict_proba = σ(w·x + b)`.

### Часть II. Реальные данные
- **EDA:** баланс классов, распределения числовых признаков, тяжёлый хвост `capital-gain/loss`, связь с образованием/семейным положением, пропуски.
- **Разбиение:** train/test = 80/20 (`stratify`); выбор моделей по 5-fold стратифицированной CV на train; тест — для итоговой оценки.
- **Предобработка (всё внутри `Pipeline`, без утечки):** `SimpleImputer` + `OneHotEncoder(min_frequency=0.01)`, `StandardScaler`, `PolynomialFeatures`, `ColumnTransformer`, собственный класс `FeatureEngineer` (`log1p` капитала, флаги, `is_overtime`, `age_group`).
- **Baseline:** `LogisticRegression` только на 5 сырых числовых признаках.
- **Улучшение (абляция, по одной идее на шаг):** M1 масштабирование → M2 категориальные признаки → M3 свои признаки → M4 полиномы 2-й степени → M5 `class_weight="balanced"` → M6 `GridSearchCV` (степень × C × веса классов) → M7 L1 → M8 `SGDClassifier(loss="log_loss", penalty="elasticnet")`.
- **Критерий выбора:** CV **PR-AUC** (подходит для несбалансированных классов). Порог классификации подбирается по out-of-fold-прогнозам на train (максимум F1).
- **Анализ ошибок:** матрицы ошибок, ROC и PR-кривые, калибровочная кривая, распределение вероятностей, recall/precision по группам (возраст, образование, пол), самые влиятельные веса.

## 7. Основные выводы

- **Синтетика:** линейной границы не хватает; качество определяется балансом «смещение–дисперсия». Степень полинома и сила регуляризации `C` — две ручки одного регулятора. Accuracy слабо чувствительна к переобучению, log-loss — сильно.
- **Реальные данные:** из-за дисбаланса 76/24 accuracy мало информативна, поэтому оценка идёт по ROC-AUC, PR-AUC и F1. Вклад каждой идеи измерен абляцией (ΔCV PR-AUC); не каждая идея улучшает метрику — выбор делается по кросс-валидации.
- **Веса классов и порог** почти не меняют ранжирование, а сдвигают компромисс precision/recall и ухудшают калибровку вероятностей.
- **Ошибки неоднородны:** качество различается между возрастными, образовательными и половыми группами — без аудита по группам модель для решений о людях использовать нельзя.
- **Что дальше:** градиентный бустинг как верхняя планка, калибровка вероятностей (`CalibratedClassifierCV`), fairness-аудит.
